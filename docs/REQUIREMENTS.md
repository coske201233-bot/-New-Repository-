# 勤怠・シフト管理システム「シフトマネジャー」要件定義書

---

## 1. システム概要・背景

### 1.1 システム名
**シフトマネジャー (Shift Manager)**

### 1.2 導入目的
医療・福祉および介護施設（複数フロア・訪問・外来・多職種）における、複雑な勤務シフト作成、休暇申請承認ワークフロー、法定年休（年5日取得義務）の自動管理、フロア別不就労時間按分集計をワンストップで実現し、管理者の業務負担軽減と職員の利便性向上を図る。

### 1.3 主要ターゲットユーザー
- **施設管理者 / シフト管理者**: 毎月の勤務表作成、休暇申請承認、年休取得モニタリング、フロア別コスト・不就労時間の把握、印刷用実績表の出力を行う。
- **施設職員 (常勤・会計年度等)**: スマートフォンやPCから自他シフトの確認、各種休暇（年休、時間休、特休、振休等）や公休変更の申請を行う。

### 1.4 システムアーキテクチャ
- **フロントエンド**: React Native (Expo SDK), React Native for Web (Desktop / Mobile PWA)
- **ホスティング**: Vercel (Web本番環境)
- **バックエンド / データベース**: Supabase (PostgreSQL, Realtime Subscriptions, Row Level Security)
- **状態管理・同期**: カスタムフック (`useAppLogic`, `useShiftData`, `useStaffData` 等) によるリアルタイム同期＋ローカルフォールバック
- **出力機能**: Web / モバイル対応の HTML5 帳票印刷エンジン (`pdfExport.ts`, `shiftExport.ts`)

## 2. 利用者区分と権限管理 (RBAC)

| ロール | 権限範囲 | 主な操作画面 |
| :--- | :--- | :--- |
| **一般職員 (Staff)** | 自身の情報閲覧、シフト閲覧、自身の休暇・シフト変更申請、個人カレンダー確認 | ホーム、出勤カレンダー、職員一覧（自カード）、申請画面 |
| **管理者 (Admin)** | 全機能アクセス、シフト直接編集・作成・削除・複製、申請承認・却下・一括処理、職員登録・編集・無効化、年休取得率ダッシュボード閲覧、フロア別不就労時間集計、監査ログ閲覧、印刷実績表出力、QRコード共有 | 全画面（上記に加え、管理・設定画面、申請管理画面、QR共有画面） |

### 2.1 認証・セッション仕様
- **職員認証**: 職員一覧からの選択＋4桁暗証番号 (PIN) または パスワード認証。
- **管理者判定**: Supabase Auth セッション (`auth.user`)、職員テーブルの `role = 'admin'`、プロフィールの管理者フラグ、およびセッション内管理者認証の多層判定。競合状態 (Race Condition) を防止する初期化ガードを完備。
- **自動更新・耐障害性**: トークン失効時の自動リフレッシュ、セッションストレージ復元、ホワイトスクリーン防止 (WSOD Guard)。

## 3. 画面一覧および機能要件

### 3.1 画面一覧
1. **ホーム画面 (`HomeScreen.tsx`)**
   - 本日の出勤者・不在者（年休、特休、振休、時間休等）のリアルタイム集計表示。
   - 当日のフロア別・職種別配置確認。
   - マイカレンダー・各種申請へのクイックナビゲーション。
2. **出勤カレンダー画面 (`CalendarScreen.tsx`)**
   - 月別・日別の全職員勤務カレンダーグリッド表示。
   - 管理者向け：シフトセルの直接編集、日付移動（月跨ぎ対応）、シフト複製、削除モーダル。
   - シフトバッジの種別別カラーコーディングおよび縮小最適化（「特X+Y」「振＋時」等の複合表示）。
   - シフト自動生成エンジン呼び出し（休日ローテーション、振休自動配置）。
3. **申請画面 (`RequestScreen.tsx`)**
   - 申請種別の選択：年休、時間休、特休、特休＋時間休、振休4、振替＋時間休、公休変更、休日出勤＋公休変更、出張等。
   - ペア日付選択（元の日付と変更先希望日）の自動バリデーション。
   - 申請可能期間のバリデーション（**15日解禁ルール**の適用）。
   - 申請履歴のカード表示（申請日、状態：承認待ち/承認済/却下）。
4. **申請承認画面 (`AdminRequestScreen.tsx`)**
   - 管理者専用。未承認申請の一覧表示。
   - 個別承認、一括承認、却下（理由入力対応）、削除。
   - 承認時のカレンダー・シフトテーブルへの自動同期・反映。
5. **職員画面 (`StaffScreen.tsx`)**
   - 全職員のカード一覧表示（役職、職種、所属、配置フロア）。
   - 個別職員の年休管理情報：1月（または4月）時点の持ち年休数、取得済み日数・時間、現在残数（〇日〇.〇〇時間）。
   - **年5日年休取得義務状況**（「達成」または「要年休〇時間」のリアルタイム表示）。
   - 個人カレンダー表示（月別シフト、申請履歴のオーバーレイ）。
   - 勤務実績表（印刷・PDF）の出力トリガー。
6. **管理者ダッシュボード (`AdminScreen.tsx`)**
   - **年休取得状況モニタリング**: 全社・部門別年休取得率、5日義務未達者の警告。
   - **週別フロア別不就労時間集計**: 2階・4階のフロア按分による週単位不就労時間集計テーブル、職員内訳ドリルダウン。
   - **職員管理**: 新規職員追加、情報編集、長期休職（産休・育休・病気休業等）の期間設定（期間外は自動で在籍復帰）。
   - **システム設定**: 曜日別（平日・土・日・祝日）の必要出勤人数（制限数）の月別設定。
   - **操作履歴（監査ログ）**: 誰が・いつ・どの職員のシフト/申請をどう変更したかの検索・フィルタ表示。
7. **QR共有画面 (`QrShareScreen.tsx`)**
   - 職員向けアクセス用QRコードの表示とURLコピー。
   - モバイルPWAインストール・ホーム画面追加の案内。
8. **ログイン画面 (`LoginScreen.tsx`)**
   - 職員氏名選択式ログイン、暗証番号入力。
9. **初期設定画面 (`SetupScreen.tsx`)**
   - 管理者パスワード設定、施設初期パラメータ設定。
10. **エラーフォールバック画面 (`App.tsx` - `ErrorFallback`)**
    - 予期せぬ実行エラー発生時の画面トラップ、ワンクリックキャッシュクリア＆再読み込みボタン。

## 4. 業務ルール・計算ロジック詳細

### 4.1 基準労働時間と年休起算日
| 職員区分 | 基準労働時間 (1日) | 起算日 (年度開始日) | 備考 |
| :--- | :--- | :--- | :--- |
| **通常職員** | **7.75時間** (7時間45分) | **1月1日** | カレンダー年基準 |
| **会計年度職員** | **7.50時間** (7時間30分) | **4月1日** | 会計年度基準 (`position` に「会計年度」を含む) |

### 4.2 年休残時間・残日数の計算規則
- **総保有時間** = `年初付与日数 × 基準労働時間`
- **消化時間** =
  - 年休（全日）: `1日 × 基準労働時間` (7.75h または 7.50h)
  - 時間休: 取得時間（0.25時間刻み、1.0h〜7.5h/7.75h）
  - 振替＋時間休: 付随する時間休の取得時間分を年休から控除
- **残時間の表示形式**:
  - `日数 = Math.floor(残総時間 / 基準労働時間)`
  - `端数時間 = 残総時間 - (日数 × 基準労働時間)`
  - フォーマット: **「〇日〇.〇〇時間」** (例: `12日3.50時間`)

### 4.3 年5日年休取得義務の管理規則
- 労働基準法に基づく年5日以上の年休取得義務を、時間基準で厳格に管理する。
  - 通常職員: **38.75時間** (7.75h × 5日) 以上で義務達成
  - 会計年度職員: **37.50時間** (7.50h × 5日) 以上で義務達成
- 未達の場合は、不足時間を **「要年休〇時間」** (例: `要年休15.5時間`) とカードおよび一覧上に強調警告表示。

### 4.4 休暇申請期間の制限規則（15日解禁ルール）
職員による休暇・シフト申請の受付期間を統制するための未来制限ルール。
- **基準判定日**: 操作時点の当日日付 (`new Date()`)
- **解禁境界**:
  - **当日が15日未満（1日〜14日）**: **翌月末日**までの申請が可能
  - **当日が15日以降（15日〜末日）**: **翌々月末日**までの申請が可能
- **過去日・当月**: 締め切り制限は行わず、過去・当月内の申請は常に受付可能。
- **違反時挙動**: 申請画面のカレンダー選択不可制御、および送信時の弾きガード（「〇月〇日以降の申請は毎月15日に解禁されます」）。

### 4.5 シフト・休暇種別と集計仕様
| シフト種別 | 出勤/休暇区分 | 労働時間換算 | 年休控除 | 画面バッジ表記 | 特記事項 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **通常出勤** | 出勤 | 基準時間 | なし | 通常 | 平日通常勤務 |
| **カスタム出勤** | 出勤 | 基準時間 | なし | 自由入力名 | 管理者が自由に入力した項目名で登録。年休・不就労計算に影響を与えない出勤扱い |
| **振休4** | 出勤 | 3.75時間 | なし | 振4 | 半日振替相当。出勤者一覧に3.75h勤務として計上 |
| **振替＋時間休** | 出勤＋休暇 | 基準 - 時間休 | 取得時間分 | 振＋時 (青枠) | 振替出勤＋時間休の複合。時間休分は年休から控除 |
| **特休** | 特別休暇 | 0時間 | なし | 特休 | 特別有給休暇（慶弔、夏季等） |
| **特休＋時間休** | 特別休暇＋休 | 0時間 | 取得時間分 | 特X+Y | 特休と時間休の併用 |
| **時間休** | 休暇 (部分) | 基準 - 取得時間 | 取得時間分 | 時Xh | 0.25時間刻みで設定 |
| **年休** | 全日休暇 | 0時間 | 基準時間 | 年休 | 全日有給休暇 |
| **公休** | 休日 | 0時間 | なし | 公休 | 定例休日 |
| **出張** | 業務出勤 | 基準時間 | なし | 出張 | 施設外勤務 |

### 4.6 休日自動割り当てエンジン (`shiftEngine.ts`)
- **目的**: 土曜日・日曜日・祝日・年末年始 (12/29〜1/3) の必要出勤人数を満たすシフトを自動生成。
- **公平ローテーション**: 登録職員リストに基づくシーケンシャル・円環状キュー (Circular Queue) による均等割り当て。前月末の最終担当者を記憶し翌月にシームレスに引き継ぐ。
- **連勤制限**: 最大連続勤務日数の監視（6連勤防止ポストプロセス）。
- **振替公休の自動付与**: 休日出勤が発生した職員に対し、直後の平日（水曜・木曜優先、または同月内）に振替公休を自動セット。
- **手動設定優先**: 管理者が手動で作成・確定したシフト (`is_manual = true`) は上書きせず保護。

### 4.7 週別・フロア別不就労時間按分集計 (`leaveUtils.ts`)
- **週定義**: 月曜日起算〜日曜日締めの週単位。
- **フロア按分比率 (Allocation Ratio)**:
  - `SC(包括)`: 2F 100%, 4F 0%
  - `2F専任`: 2F 100%, 4F 0%
  - `4F専任`: 2F 0%, 4F 100%
  - `SA`: 2F 50%, 4F 50%
  - `フォロー`: 2F 50%, 4F 50%
  - `2F/4F兼務`: 2F 50%, 4F 50%
  - `事務` / `無効・入職前`: 集計対象外 (除外)
- **対象不就労時間**: 時間休、年休、特休等の不在時間。
- **集計結果**: 週ごとの「2F計」「4F計」「週合計」、および職員別内訳テーブル。

## 5. データモデル仕様 (Database Schema)

### 5.1 テーブル定義概要
- **`staff`**: 職員マスター。ID、氏名、職種、役職、所属フロア、土日休みフラグ、期初年休保有数 (`initial_leave_days`)、長期休職期間 (`leave_start_date`, `leave_end_date`)、PIN、承認状態。
- **`shifts`**: 日次シフトデータ。ID (UUID)、`staff_id`、`date` (YYYY-MM-DD)、`type` (シフト種別)、`hours` (時間数)、`is_manual` (手動保護フラグ)、`status`。
- **`requests`**: 休暇・変更申請。ID (UUID)、`staff_id`、`staff_name`、`date`、`type`、`status` (`pending` / `approved` / `rejected`)、`reason`、`details` (変更前後のペア日付等)。
- **`audit_logs`**: 監査ログ。ID、`operator_name`、`action_type` (`SHIFT_UPDATE`, `SHIFT_DELETE`, `REQUEST_APPROVE`, `REQUEST_REJECT`, `REQUEST_DELETE`)、`target_date`、`target_staff_name`、`details`、変更前後のスナップショット (`before_data`, `after_data`)。
- **`app_config`**: 施設全体設定。月別出勤上限数、ロック月設定、祝日マッピング。

## 6. 非機能要件

1. **耐障害性と即時性 (Resilience & Realtime)**:
   - オフライン時やネットワーク瞬断時にも操作が継続できるようローカルキャッシュと楽観的UI更新を実装。
   - ゾンビデータ（削除済みレコードの再同期復活）の完全排除ロジック。
2. **クロスプラットフォーム対応**:
   - iOS / Android / Web (Desktop & Mobile) のレスポンシブデザイン。
   - Web PWAによるホーム画面追加、全画面ネイティブアプリライクなUX。
3. **帳票印刷品質**:
   - A4横/縦に最適化されたCSS `@media print` レイアウト。
   - 印鑑枠、月次集計サマリー、フロア別区分を含む公的提出品質の「勤務実績表」。
4. **セキュリティ・監査証跡**:
   - 重要操作（シフト改変、申請承認・却下・削除）の監査ログ自動記録。
   - パスワード・PINのハッシュ化およびRLS (Row Level Security) 整備。
